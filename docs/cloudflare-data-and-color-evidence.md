# 配色依据、用户记录与 Cloudflare 数据方案

更新：2026-10-18。状态：Web 训练和本地档案已实现；Cloudflare 后端仅评估与设计，尚未创建数据库、接入登录或上传用户记录。项目版本仍为 0.1.0。

## 配色：把证据与设计选择分开

2009 年的红/蓝研究报告了任务相关差异，例如红色条件下细节任务表现、蓝色条件下创造任务表现不同。它没有证明某个网页色值能普遍提高记忆。后续研究也受到任务难度、颜色呈现方式等因素影响；2020 年元分析在纠正发表偏差后，对红色影响智力任务表现未发现有说服力的证据。不能把照明中的蓝光效应直接套到蓝色网页背景，也不能将偏好、舒适度等同于训练迁移。

因此本轮选用低饱和蓝绿色作为导航、按钮和分组提示，近白训练区、浅灰绿页面底色与深色正文。它是一项界面可读性与层次设计选择，没有“此颜色提升记忆 X%”的承诺。去掉训练区的笔记纸网格背景，使用清晰的数字字体。错误仍有红色边框和文字反馈；色词冲突的刺激色保持原任务定义，不被主题色替换。桌面生产力页面的现有独立主题不受此 Web 样式覆盖。

| 用途 | 色值 | 依据/作用 |
| --- | --- | --- |
| 页面底色 | `#f1f5f4` | 承托训练区域，作为中性背景 |
| 卡片与训练网格 | `#ffffff` | 保持刺激边界清楚 |
| 正文和数字 | `#173436` | 与背景保持高对比 |
| 次要正文 | `#4f6564` | 仍按普通文字对比度检查 |
| 操作与强调 | `#125f57` | 白色按钮文字对比度通过 4.5:1 |
| 分组提示 | `#deefea` | 小面积强调，不改变题目目标 |

测试检查主要文本/背景配对达到 WCAG 普通文字 4.5:1。该对比度标准支持可读性，不是记忆提升试验。若后续评估颜色效应，应固定题型、亮度和显示条件，随机分配主题，预先定义指标与分析方法，保留主题版本，不能根据同一个人的前后分数直接归因颜色。

来源：

- [Mehta 与 Zhu，2009](https://pubmed.ncbi.nlm.nih.gov/19197022/)
- [任务难度与红蓝颜色研究，2016](https://www.frontiersin.org/journals/psychology/articles/10.3389/fpsyg.2016.00784/full)
- [红色与认知表现的元分析，2020](https://pubmed.ncbi.nlm.nih.gov/32696125/)
- [WCAG 文字对比度说明](https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum)

## 已实现的训练与记录

原六个核心方法、四个小游戏、启动器、弹窗、番茄钟等入口保留。数字训练在同一旧路由内提供：

- 基础：全程显示数字的舒尔特搜索，4×4 / 5×5。
- 进阶：原来的分组观察、翻盖顺序回忆与完整路径挑战，4×4 每组 4 个、5×5 每组 5 个。
- 切换难度或尺寸生成新布局；按旧布局回退仍可用。重练布局会标记并保留结果，但从新题曲线排除。

新增记录包含：本地档案 ID、随机浏览器安装 ID、规则版本、尺寸、子模式、单调时钟测得的总用时、错误数、布局、主题版本、粗粒度显示环境、是否复练。记忆模式总用时包含观察与回忆，不能与基础搜索直接比较。页面切后台或尺寸改变会取消/重置未完成轮次，避免把后台停留混入完成分数。

本地数据键保持 `focus-lab-training-records`，持久化结构从 2 升至 3。旧记录、小游戏、计划和布局原样保留；旧记录不补造档案归属、规则版本或毫秒精度。新身份只附在新记录上。现有本地存储尚未在真实用户历史浏览器上迁移演练，已用旧结构样本测试。

记录页可保存昵称和导出全部 JSON 备份。此 ID 是应用随机生成的浏览器内档案，不是实名、硬件标识或可靠的独立人数；同一浏览器多人共用会混用档案。清理站点数据、隐私窗口结束或换浏览器会丢失/改变身份。当前无云同步，自动恢复、备份导入和多用户档案切换尚未实现。不能将当前本地保存宣传为永久云端保存。

进步曲线按档案、安装、模式、尺寸、规则和显示环境分组，只显示新布局记录；旧记录与复练仍在明细中。至少 6 轮零错误后，用前 3 轮与最近 3 轮的用时中位数计算变化。更快但错误更多的轮次不用于“用时提升”百分比。百分比是此任务用时变化，不是记忆力提升百分比，也不证明因果或现实迁移。当前粗粒度环境只区分窄/宽视口与粗/精指针，未记录真实输入方式、屏幕亮度或刷新率，不足以支撑严格研究控制。

## Cloudflare 能否支持

结论：可以支持持久化的个人训练档案和研究数据管线，推荐沿用静态站并增加 Workers/Pages Functions + D1；R2 用于备份或获授权的研究数据文件。单独开启 Web Analytics 只能提供访问与性能统计，不能替代逐用户训练数据库。

```text
Focus Lab 页面
  → 同源 /api（登录校验、校验记录、幂等与限流）
  → D1（用户、安装、训练、授权记录）
  → 个人曲线 API（只返回登录者数据）
  → 研究导出任务（按授权过滤、去除直接身份）
  → R2（备份/版本化研究文件，私有访问）
```

不要把数据库 API 凭据放进页面。Workers 从经验证的登录会话确定 user_id，不能相信请求体传来的 user_id。查询必须按当前用户过滤；站内 `/api/` 请求不进入公共 Service Worker 缓存。本轮已在现有 SW 排除该路径，未来仍需后端 `Cache-Control: private, no-store` 和账户退出清理。

举例：1000 人每天 10 轮，摘要约 1 万行/日；若每轮另写 25 次点击，已约 26 万行/日，尚未计索引，超过免费写额度。因此初期适合“每轮一行摘要＋一行压缩事件批次”或按批准采样记录细节。不要逐帧上传动画或每秒心跳。每个 session_id 用唯一约束实现离线重试幂等，并记录服务器接收时间与客户端时钟质量。

## 手机型号唯一码为什么不可行

手机型号描述产品型号，同型号的很多手机相同，不能当唯一 ID。一般网页没有可直接获取 IMEI、系统序列号等永久硬件 ID 的标准接口；User-Agent/Client Hints 还受到浏览器限制。组合屏幕、字体、IP 等做指纹既不稳定也不等于一个人：更新、共享设备、隐私设置和网络变化都会造成混淆。

推荐三个层次：

1. `user_id`：经用户登录建立的稳定账号 ID，跨设备保持；可采用邮箱验证或通行密钥，具体认证方案后续选型。昵称不是认证。
2. `installation_id`：应用随机生成，区分该账号下的浏览器安装；清理后允许生成新 ID，不偷偷重新识别。
3. `session_id`：每轮训练的唯一 ID，用来防止重复上传，不等同于登录会话 ID。

游客使用本地档案；登录时由用户明确确认是否合并历史记录。已有客户端记录只视为用户提交的历史，不能凭上传就变成可信科研数据；也不能从设备推断实名或真实独立人数。认证用户也可能多人共用账号，研究中需要写明这一限制。

来源：[W3C 隐私工作组的指纹识别说明](https://www.w3.org/TR/fingerprinting-guidance/)、[Chrome Client Hints 与设备信息](https://developer.chrome.com/docs/privacy-security/user-agent-client-hints)。

## 未来数据库最小契约

| 表 | 关键内容 |
| --- | --- |
| users | 稳定 user_id、认证主体引用、显示昵称、创建/删除状态；不存硬件序列号 |
| installations | installation_id、user_id、注册时间、必要的显示与输入环境；同用户可多安装 |
| training_sessions | session_id、user_id、installation_id、规则/应用/主题版本、模式、尺寸、布局或种子、开始/结束时间、完成/取消状态、各阶段耗时、错误/重记、是否复练、来源可信级别 |
| response_batches | session_id、批次序号、刺激/目标、首次实际呈现偏移、响应偏移、实际输入方式、正确性、前后台/尺寸中断；事件数据以不可变批次存储 |
| consents | user_id、目的（产品同步/研究/模型训练）、说明版本、同意与撤回时间；三个目的分别记录 |
| exports | 数据集版本、授权快照、纳入/排除标准、生成时间、导出范围与审计信息 |

`UNIQUE(user_id, session_id)`、事件批次唯一约束与内容哈希用于幂等与冲突检查；不以覆盖旧会话来“修正”不一致上传。后台先验证上下界、规则版本、事件顺序与总时长一致性，再存记录；客户端报告不能作为防作弊认证。授权表与研究数据权限单独控制，研究导出不含登录标识或昵称映射。

### 数据保留与研究用途

- 用户主动使用的同步服务和可选研究授权分开。拒绝研究/模型训练不影响基本训练与个人记录。
- 正式收集前公开用途、字段、保留期限、导出/删除方式和退出后处理；有未成年参与者时另设计适用的流程。具体法律与伦理要求需根据地区、研究机构与目的确认，本方案不是合规结论。
- 建议个人档案保留至用户删除或按事先公示的闲置规则处理；原始研究事件先采用例如 12 个月的待评审期限，而非默认永久。将实际选定期限写入配置与说明后才收集。
- 稳定 ID、去掉姓名或哈希并不自动构成匿名化。可重新关联个人的研究数据仍按个人数据控制访问。
- 备份有独立到期规则与删除标记。恢复备份后要重放删除/撤回，防止已经删除的数据重新出现。
- 自选练习人群有选择偏差；熟悉效应、练习剂量、退出者、设备差异和睡眠等因素影响曲线。若要证明训练改善一般能力，需要独立测试、对照设计与预定义分析；不能用站内留存曲线直接证明训练有效。
- 若“训练数据”指 AI 模型训练，须另设明确授权、数据集版本、排除撤回记录与访问边界。本轮没有将任何数据送入模型，也没有默认上传。

## 下一阶段实际接入前的验收

账号跨设备关联、游客历史明确合并、越权读取拒绝、重复上报幂等、离线重试、事件校验、撤回研究授权、用户导出/删除、备份恢复、额度耗尽、本地未同步提示、失败不丢记录、旧数据不可伪装为新研究记录。后端通过这些检查后再开启真实用户云端收集。
